# Daily Reading and Image Input Design

## Goal

Give Thai learners ages 10–13 two guided ways to supply English text to the existing LinguBreak sentence analyzer:

1. choose a sentence from a fresh learner-friendly daily paragraph; or
2. choose a sentence extracted from an uploaded image or a mobile camera photo.

The existing textarea remains the final editable sentence input. The current LinguBreak prompt, `AnalysisResult` schema, RAG pipeline, cache/provenance behavior, OpenRouter provider policy, and results UI remain unchanged.

## Audience and Learning Contract

- Target ages: 10–13.
- Target level: CEFR A2–B1.
- A daily reading contains 3–4 sentences and 60–100 words.
- Topics must be neutral, educational, and suitable for school-aged learners.
- Disallowed topics include graphic violence, sexual content, drugs, self-harm, hate, sensational crime, and partisan persuasion.
- Learners analyze one sentence at a time; the feature does not broaden LinguBreak into paragraph analysis.

## Content Provider Decision

Use the MediaWiki Action API on Simple English Wikipedia as the source provider. The source is commercially reusable under CC BY-SA when the product links to the source, identifies the adaptation, and displays the applicable license. Caffeine will publish each generated adaptation under CC BY-SA 4.0 and show all three notices beside the reading.

Do not use NewsAPI, GNews, or NewsData in this phase. Their entry tiers do not provide a clean combination of production use, complete source text, and clear reuse rights. Do not implement the Guardian Open Platform yet; commercial use requires a negotiated license and custom pricing.

The source adapter must remain small enough to replace later. It returns source title, canonical URL, extract, and license metadata. It must not introduce a provider marketplace or speculative multi-provider fallback.

## Daily Reading Flow

1. `GET /api/daily-reading` selects one topic from a local, reviewed allowlist using the UTC calendar date.
2. The server requests that page's plain-text introduction from `https://simple.wikipedia.org/w/api.php`.
3. OpenRouter rewrites only the supplied facts into an original 3–4 sentence A2–B1 paragraph using `openrouter/free` and strict JSON Schema output.
4. A local Zod schema validates the title, paragraph, and sentence array.
5. The route attaches authoritative source URL, source title, adaptation notice, license name/link, and generated date. These provenance fields are never generated by the model.
6. The route sends public 24-hour cache headers so normal traffic does not regenerate content for every learner.
7. The UI displays the paragraph and source/license attribution. Selecting a sentence copies it into the existing textarea; analysis starts only when the learner presses the existing action button.

The topic allowlist favors science, nature, animals, geography, everyday technology, sport, arts, and practical life. Random unrestricted pages are not allowed because topic filtering after acquisition creates an unnecessary child-safety risk.

## Image and Camera Flow

1. “Scan Text” opens the preserved OCR workflow inside the existing input card.
2. “Choose image” uses a standard file input accepting JPEG, PNG, and WebP up to 10 MB.
3. “Take photo” uses a separate standard file input with `accept="image/*"` and `capture="environment"`, allowing supported mobile browsers to open the rear camera without a camera SDK.
4. Both inputs use the existing validation and preview path.
5. OCR runs locally through the existing Tesseract adapter. Normal input therefore does not require or call Gemini.
6. Extracted text is split into sentences with `Intl.Segmenter` when available and a conservative punctuation fallback otherwise.
7. The UI shows valid sentences of 1–500 characters. Selecting one copies it into the existing textarea for optional editing and analysis.

The existing Gemini OCR route and adapter remain intact but dormant. PDF, Word, plain-text document parsing, multi-image batches, cropping, and image enhancement are outside this phase.

## UI Structure

The `SentenceInput` card keeps its textarea, example selector, model display, and analyze/reset actions. Above the textarea it adds two source buttons:

- **Today’s Reading** — expands the daily paragraph and its selectable sentences.
- **Scan Text** — expands image upload/camera controls, OCR progress, extracted text, and selectable sentences.

Only one source panel is open at a time. Choosing a sentence closes the panel, populates the textarea, and leaves the learner in control of submission. Manual typing and pasted text continue to work without becoming a third labeled source mode.

## Interfaces and Boundaries

- `DailyReadingSource`: source title, URL, extract, and license metadata returned by the MediaWiki adapter.
- `DailyReading`: validated learner title, paragraph, sentence list, date, source provenance, adaptation notice, and license link returned to the UI.
- `splitEnglishSentences(text)`: shared deterministic helper used by OCR text and available for daily-response consistency checks.
- `GET /api/daily-reading`: public, read-only, cached route. It accepts no arbitrary URL, page title, prompt, provider, or model from the client.
- Existing `POST /api/analyze`: unchanged.
- Existing `POST /api/ocr`: unchanged and not used by the default scan flow.

No new database table is needed. The daily response is disposable derived content with source provenance and HTTP/CDN caching; persistent editorial history is deferred until there is a real moderation workflow.

## Failure Handling

- MediaWiki unavailable or invalid source extract: return a sanitized `503` response.
- OpenRouter authentication, rate limit, empty response, or schema failure: return a sanitized `503` response without falling back to direct providers.
- Daily-reading UI failure: show a retry action while manual input and image scanning remain usable.
- Unsupported or oversized image: reject before OCR with existing validation copy.
- OCR returns no usable sentence: keep extracted text editable and ask for a clearer image or manual correction.
- Never expose API keys, raw upstream bodies, model reasoning, or unsafe candidate content.

## Verification

- Contract check for valid and invalid `DailyReading` payloads.
- Deterministic checks for date-to-topic selection and sentence splitting.
- Route checks for success metadata and sanitized upstream failures.
- OCR checks for upload validation and camera-input attributes through static component inspection.
- Confirm `OPENROUTER_API_KEY` remains the only required LLM key for this flow.
- Run `npm run check:env`, `npm run check:routes`, `npm run typecheck`, `npm run lint`, and `npm run build`.
- Run a focused live call to MediaWiki and the daily-reading route when the configured OpenRouter free route is available.

## Explicit Non-Goals

- Whole-paragraph LinguBreak analysis.
- General news aggregation or unreviewed random topics.
- Guardian commercial integration before a license is purchased.
- Scheduled jobs, queues, AWS changes, editorial dashboards, or moderation tools.
- PDF, Word, text-file, audio, or multi-image import.
- New OCR providers, camera libraries, provider fallback, retries, or health graphs.
